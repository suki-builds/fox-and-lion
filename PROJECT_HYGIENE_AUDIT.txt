Fox and Lion — Project Hygiene Audit
Date: 2026-08-23

Full sweep of tracked files, untracked files, dependencies, and live Vercel
env vars, cross-referenced against actual usage. Findings below, roughly
ordered by how much it matters.

================================================================
LIVE CREDENTIAL DEBT (Vercel production)
================================================================

Three DatoCMS-era tokens are still set in Vercel despite the DatoCMS
integration being fully removed from code months ago:

  - DATOCMS_API_TOKEN (Production, Preview — added 28d ago)
  - DATOCMS_CONTACT_FORM_TOKEN (Production, Preview — added 5d ago)
  - DATOCMS_PITCH_SUBMISSION_TOKEN (Production — added 13d ago)

Zero references to any of these in the codebase (git grep clean). These
are live write-scoped API tokens for a service you no longer use, sitting
in production config. Worth revoking in DatoCMS's dashboard and removing
from Vercel (vercel env rm <name> production).

================================================================
DEAD CODE (confirmed zero references)
================================================================

- slices/ directory — CardGrid/, Hero/, ResourceLinks/ (both the tracked
  model.json files and the untracked .tsx stubs + index.ts), all
  scaffolded by `prismic init`. Nothing in app/ imports SliceZone or any
  of these components — the homepage is hand-built React
  (app/(public)/page.js), not slice-driven. Confirmed further:
  customtypes/homepage/index.json's own slices.choices is {} — not even
  wired up on the Prismic side.

- customtypes/homepage/index.json — the "homepage" Prismic page type
  itself is never fetched anywhere (getByUID('homepage', ...) doesn't
  exist in the code). It's tracked only because `prismic push` refuses to
  delete remote models it can't see locally — a defensive keep, not a
  used one.

- lib/supabase/client.ts — a browser-side Supabase client factory, zero
  imports anywhere. Both form submissions go through server API routes
  using lib/supabase/server.ts instead, so this browser variant was
  written but never wired up.

- prismicio-types.d.ts (untracked, auto-generated by the Prismic CLI) —
  zero references. Safe to delete; regenerate with `npx prismic pull` if/
  when the slice work is ever picked back up.

================================================================
STALE / MISLEADING CONFIG
================================================================

- PREVIEW_SECRET in .env.local.example — documented as securing an
  /api/preview route, but that route doesn't exist in the codebase, and
  the var isn't even set in Vercel. Fully vestigial.

- prismic.config.json's routes — maps analysis_post/news_post to
  /analysis-post/:uid and /news-post/:uid, which don't match the site's
  real URL structure (/analysis/[slug], /news/[slug]). Only consumed by
  the Prismic CLI's own pull/push tooling, not app runtime, but would
  mislead anyone who assumes it reflects real routing.

================================================================
DEPENDENCY MISMATCH
================================================================

- package.json: react/react-dom pinned at 18.3.1, but @types/react is
  ^19.2.18 — a major-version gap between runtime and its type
  definitions. Currently harmless (the only tracked .ts files are the two
  plain Supabase client factories, no JSX/React types involved), but it's
  a trap waiting for the first .tsx component.

- @types/node: ^26.2.0 is unusually high — worth a sanity check against
  whatever Node version this actually deploys on.

================================================================
DOCUMENTATION DRIFT
================================================================

- README.md's "What's already built" list only mentions Home/About/
  Contact — doesn't mention Careers, Submission Guidelines, or
  Submission Portal, all of which are live and linked from the footer.

- Fox_and_Lion_Privacy_Policy.md (untracked, repo root, 71 lines) looks
  like the original markdown source that was hand-copied into
  app/(public)/privacy-policy/page.js (148 lines, the live page). It's
  now a stale, unreferenced duplicate.

- Minor copy inconsistency, not code: the privacy policy page uses
  enquiries@advancedgrowinglabs.com in three places, while About/
  ContactForm/SubmissionPortalForm all use
  foxandlion@advancedgrowinglabs.com — same domain, different mailbox
  names for what reads as the same "contact us" purpose.
